# Governance

## Project Leadership

This project is maintained by [Scott Schreckengaust](https://github.com/scottschreckengaust) (BDFL).

All final decisions on direction, architecture, and releases rest with the maintainer.

## Decision Making

- **Architecture decisions** are documented in [adr/](adr/) as Architecture Decision Records
- **Feature prioritization** uses P0/P1/P2 labels on GitHub Issues
- **Contributions** are reviewed via pull requests (see [CONTRIBUTING.md](CONTRIBUTING.md))

## Contributions

Anyone can contribute via pull requests. The maintainer reviews and merges at their discretion.

Large changes (new constructs, breaking API changes) should open an issue for discussion before submitting a PR.

## Releases

There is no fixed release cadence. The `main` branch is always deployable. Breaking changes are communicated via commit messages and release notes.

## Changes to Governance

This governance model may evolve as the project grows. Changes will be communicated via pull request to this file.
